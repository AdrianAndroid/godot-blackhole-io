## B.4 改造任务（按优先级，可分阶段提交）

### P0 城市形态：让画面"像一个城市"（收益最大）

1. **连续道路**：把当前"格心一块 4×4 路砖、间距 8"改成连续路网。建议：地面铺连续混凝土基底 + 在街区边界（`x/z = ±4, ±12, ±20, ±28, ±36`）铺 2~3 单位宽的沥青街带，路口处放 `road_crossroad`/`road_intersection`；或用路砖按 8 单位无缝平铺再叠街带。要求截图里**看不到地面缝隙**，街道有明确边界。
2. **中心区补建筑**：中心 3×3 格只保留玩家出生格 `(0,0)` 空置，其余 8 格正常生成建筑与道具；塔预留区仍然保证 `(24,30)` 半径 3 + 4 米净空。
3. **提高密度**：每格改成一栋"主建筑 + 1~2 栋附属楼/堆叠物"，或把格距从 8 收到 7 并维持合法间距（`validate_layout` 的重叠/出生/高塔/成长可达/四分区校验必须继续通过）。视觉目标：出生点视野内至少有 8 栋建筑可见。
4. **填补空旷区**：`x>26` 的整片禁区改为只在塔周围留空，其余照常生成。
5. **验证**：`city_generator_test` 的 100 种子必须全通过；新增断言"出生点 20 米内的建筑数量 ≥ 8"和"道路覆盖整张地图（无空隙）"；`spawn_manager_test` 的四类分区与变体断言继续通过。

### P1 地面与光照：修正色偏和过曝

- 地面从 `a8b98b` 改为浅灰混凝土（建议 `#c3c8cd` 一带，饱和度低），草地作为独立小块（可由实例化小平面/贴地 quad 实现）而不是整片底色。
- 若保留 `TONE_MAPPER_LINEAR`，把太阳能量从 1.25 降到 0.85~0.95、环境光 0.32 提到 0.40~0.50，避免浅色表面发白；或改用 `TONE_MAPPER_FILMIC` 统一压高光。**以截图为准**，不要凭参数判断。
- 水面：换成有细微波纹/反光的材质（可为水面加一层轻微法线或 shader），避免纯色平板；水面位置随城市生成变化（如河道）可选。
- 保证 `city_sample_test`（24 个模型、四类分区、无候选目录导入）继续通过。

### P2 黑洞与吞噬反馈：补齐"爽感"

- Shader：加亮外环（提高 rim 亮度/宽度）、外圈加一层柔和的地面光晕（可用第二个加法混合圆环 mesh，或 shader 输出 emission 到地面）、边缘加旋转颗粒（billboard 粒子或 shader 噪点）。
- 洞体厚度：用短圆柱/凹陷圆盘替代纯平面，或在平面下方加深色圆柱侧面。
- 吞噬：在物体位置弹"+N"飘字（按 `score`，击倒按 `knockdowns` 显示连击 `×N`），并加吸附粒子与轻微屏幕震动；这些必须由 `completed` 事件驱动，**不得在动画回调里加奖励**。
    - 约束：飘字节点必须随 Session 释放；不能影响 `snapshot()` 与任何逻辑断言；透视/正交下逻辑快照必须一致（`match_controls_test`）。
- 黑洞视觉尺寸可配合成长曲线调整（视觉半径与 `effective_radius` 必须共用同一配置值，`hole_visual_test` 有断言）。

- 要求：所有 HUD 元素 `safe_rects` 在 432×960 内；`visual_regression` 的 12 个检查点必须能稳定截图（不能有跨帧闪烁/随机动画）。

### P4 终点塔：造型与演出

- 造型：改为参考视频里的"超高深蓝塔"量感（可用 `skyscraper_b` 拉高 + 深蓝金属材质 + 顶部/底部发光条），不要金色覆盖材质满屏糊脸。
- 尺寸：塔身高度与占地分离（占地半径仍 3.0 用于判定），视觉高度可以到 20~30 单位，但**不能挡住整个屏幕**。
- 演出：塔出现时镜头轻微推近/短暂定格，吞噬时整根塔从下往上被"吸进"洞里（可复用 `Swallowable.advance` 的下沉逻辑，但需单独参数），完成后才结算胜利。
- 触发：触发位置建议固定为名称可见的地标（如"终点塔"），并在 HUD 给出"抵达终点"文案，与视频一致。
- 不改规则：塔仍然无视普通半径资格，仍然只发胜利、不发普通奖励。

### P5 玩法张力（可选，但要先和用户确认数值）

- 唯一大对手从 `1.80` 提到能对满级玩家仍有威胁的量级（如 3.5~4.0），或让对手沿路线经过玩家出生区；
- 击倒奖励从 60 分提高到目标的 5%~10%；
- 不允许引入导航/寻路/AI 追击（设计明确"不做完整 AI"），只能改路线、速度、半径、奖励。
- 任何数值改动必须同步 `tests/` 与 `openspec/changes/add-video-referenced-mvp/specs/` 相关说明。

## B.5 验收方式（每阶段结束都要跑，贴出证据）

```bash
# 1) 编辑器导入检查
/usr/local/bin/godot --headless --path . --editor --quit

# 2) 全量逻辑 + 整局测试（必须 0 失败；当前基线 299 checks / 14 suites）
```

- 验收边界照旧：Mac 验收不证明抖音兼容；像素回归不代表主观美术复刻；音效测试不代表听感
